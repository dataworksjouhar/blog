> Everything in this project is synthetic. The restaurant group, its warehouse and every figure were generated by code I wrote. It is not based on any real company's data.

In a Kuwait central warehouse, one whipping cream had two item codes. At the cycle count, one code showed **180 bottles extra** and the other **15 cartons missing**. In litres, the difference was **zero**. Nothing was missing, but 180 litres were about to expire under a code nobody ordered. Across six GCC markets, unifying **625 item codes into 150** showed that fixing codes like this would save **7,676 KWD** of stock from expiring. Written rules did most of the matching, AI handled 17 codes, and a person decides every uncertain case.

## The problem

A restaurant group with burger, cafe, Japanese, seafood and pizza kitchens in six markets buys the same products everywhere. But each market names and counts them its own way. Kuwait buys whipping cream in 1-litre bottles. Qatar buys cartons of 12. The UAE records it per litre. Bahrain's list has typos, and some KSA items are written only in Arabic.

Nobody can add those numbers up, so nobody can compare stock, cost or waste across the region.

The same problem hides inside one country. In Kuwait, when a second cream supplier was added, someone created a new code, `WHIPPING CREAM - SUPPLIER 2`, instead of linking the supplier to the existing item. Outlets kept ordering the old code, so fifteen cartons sat under the new one and aged.

![The whipping cream case: 180 bottles extra on one code, 15 cartons missing on the other, and the same 1,456 litres on both sides once counted in litres](/images/inventory-intelligence-whipping-cream.png)

That is the part I wanted a warehouse manager to see: two variances on paper that are really one data problem, and an expiry loss that no forecast would ever catch.

## How I built it

I generated the data myself: six country item lists (625 codes behind 150 real items), Kuwait warehouse stock by batch, 90 days of deliveries to 16 outlets, and a cycle count. I planted five problems, each one simple enough to explain in a sentence. The same item under different names. Different units. Two codes for one item in the same market. Look-alike items that must never merge, like a 150 g and a 200 g beef patty. And inactive items still holding stock. I also kept an answer key, used only to check the result, never to produce it.

The matching works the way a careful person would work. First, clean each name: drop the pack size, supplier tags, category prefixes and words like "NEW", and expand abbreviations, so `CHKN BRST B/L` becomes `CHICKEN BREAST BONELESS`. Then compare names word by word under one rule: **every word must find its partner**. A one-letter typo still finds its partner. "Diet" in Diet Cola does not, and a number that differs (150G against 200G) always means a different item. Finally, every code converts to kilograms, litres or pieces, so a carton of 12 is simply 12 litres.

AI only came in where rules could not know the answer. A rule cannot know that Hamour in Kuwait is Grouper in the UAE, or read لومي (dried lime) in a KSA item list. Those 17 codes went to Claude, each with a short list of candidates and written instructions: a different size or variant means a different item, and never force a match. It matched all 17 correctly. Every AI match still waits for a person.

![How whipping cream was matched across five markets: each code shows its unit conversion, the rule that matched it, and why](/images/inventory-intelligence-matching.png)

## The turning point: checking before trusting

Two moments made the work better, and both came from checking it rather than trusting it.

The first run merged salted and unsalted butter. The words look almost the same, and my spelling rule was too loose. The answer key caught it, and I tightened the rule to allow a one-letter difference only.

Later I tested the cleaning with spellings that real item lists use: `12 X 1 L`, `20 LTR`, `1 KGS`, `CREAM_NEW`. The rules missed all eight test codes. But they did not merge anything wrongly. The leftover number kept each code apart, so the result had 158 items instead of 150, with every extra one waiting for review. I widened one pattern to accept spaces and the common unit spellings, and the result came back to 150 with no wrong merges.

That is the design choice I care most about. A missed match costs a review. A wrong merge corrupts stock value and every report built on it. So every rule fails in the safe direction.

## What changed

The result is a three-step page a warehouse manager can use without training: see the risk, find the cause, act on it. The dashboard leads with the finding and the stock at risk. Item unification shows each case with how it was matched and a proposed action to approve or reject. The action tracker records every decision with its time and exports to Excel.

![The dashboard: the finding first, then the featured whipping cream case](/images/inventory-intelligence-dashboard.png)

Behind it sits an Excel stock health report built on live formulas: aging and expiry by batch, slow and non-moving items, Min/Max with suggested order quantities, and the cycle count by code and by GCC item. Measured by code, count accuracy is 44%. Measured by GCC item, it is 69%. The gap is not lost stock. It is the same items counted under two codes. The 7,676 KWD figure comes from this report too, so anyone can [download it](/inventory-intelligence/Kuwait_Stock_Health_Report.xlsx) and check the formulas.

A guided tour takes a first-time visitor through all of it in about 90 seconds, and the tour does the clicking.

## What I would tell another analyst

**Check the item data before blaming the forecast.** Most of the expired stock here, 1,356 of 1,952 KWD, sat under duplicate codes that outlets never ordered. No forecasting model fixes that.

**Use rules first, and AI only for meaning.** Rules matched 608 of 625 codes, and every one of those matches can be read and explained. AI earned its place where rules cannot reach: synonyms and another language.

**Never trust a match nobody can explain.** Every decision in this tool shows its reason, and every uncertain one waits for a person. That is what makes a warehouse manager trust it, and it is what an inventory analyst does every day with any system's output.

The data is synthetic, so real item lists will bring problems this one does not have. If you are working on item data across markets and want to compare notes, I am happy to talk.
